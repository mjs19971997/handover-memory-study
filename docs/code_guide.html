۱. این پژوهش چه می‌پرسد

وقتی کاربر تلفن همراه حرکت می‌کند، شبکه او را از یک سلول به سلول دیگر می‌سپارد؛ به این کار هندآور (handover) می‌گویند. بعضی هندآورها بی‌فایده‌اند: کاربر مدت کوتاهی در سلول تازه می‌ماند یا کیفیتش بهتر نمی‌شود. خیلی از روش‌ها برای کم‌کردن هندآور بی‌فایده «حافظه» دارند: یادشان می‌ماند که هندآورهای قبلی در هر مکان چه نتیجه‌ای داشته‌اند و تصمیم بعدی را با آن تنظیم می‌کنند.

همه‌ی این روش‌ها یک فرض پنهان دارند: نتیجه‌ی هندآور در یک مکان، درباره‌ی هندآور بعدی در همان مکان چیزی می‌گوید. این پژوهش همین فرض را می‌سنجد:

  • در کدام محیط‌ها حافظه‌ی مکانی به قاعده‌ی ساده‌ی A3 کمک می‌کند و در کدام محیط‌ها ضرر می‌زند؟
  • آیا می‌شود این را از پیش فهمید؛ یعنی فقط از روی لاگ کار عادی شبکه (بدون هیچ حافظه‌ای)؟

برای پاسخ، دو قاعده روی ورودی‌های کاملاً یکسان اجرا می‌شوند: کنترل (A3 ساده) و قاعده‌ی حافظه‌دار (همان A3 به‌اضافه‌ی یک جمله‌ی حافظه). تفاوت نتیجه‌ی این دو، اثر حافظه است. جدا از این، از لاگ اجرای کنترل یک شاخص تکرارپذیری حساب می‌شود و بررسی می‌شود که آیا این شاخص اثر حافظه را پیش‌بینی می‌کند.

۲. چند واژه که لازم است

واژهمعنا

A3قاعده‌ی استاندارد 3GPP: اگر سیگنال همسایه به اندازه‌ی یک حاشیه از سلول فعلی قوی‌تر شد و این وضع مدتی ماند، هندآور کن

۴. نصب Python و آماده‌سازی، گام به گام

این گام‌ها برای ویندوز نوشته شده‌اند؛ در لینوکس و مک فقط گام نصب Python فرق دارد.

  1. نصب Python. از نشانی https://www.python.org/downloads/ نسخه‌ی 3.12 را بگیرید و نصب کنید. در اولین پنجره‌ی نصب، تیک گزینه‌ی Add python.exe to PATH را بزنید؛ اگر این تیک را نزنید، فرمان python شناخته نمی‌شود.
  2. بازکردن پنجره‌ی فرمان. کلید ویندوز را بزنید، PowerShell را تایپ و باز کنید.
  3. آزمودن نصب. این فرمان را بزنید؛ باید شماره‌ی نسخه چاپ شود:
python --version
  1. گرفتن مخزن. اگر git دارید:
git clone https://github.com/mjs19971997/handover-memory-study.git
cd handover-memory-study

اگر git ندارید، در صفحه‌ی مخزن روی دکمه‌ی Code و سپس Download ZIP بزنید، فایل را باز کنید و در PowerShell با فرمان cd به پوشه‌ی بازشده بروید (مثلاً cd C:\Users\me\Downloads\handover-memory-study-main).

  1. نصب کتابخانه‌ها. این فرمان چهار کتابخانه‌ی numpy، pandas، scipy و matplotlib را با همان نسخه‌هایی که آزمایش‌ها با آن‌ها اجرا شده‌اند نصب می‌کند:
pip install -r requirements.txt

از این پس همه‌ی فرمان‌ها را در همین پوشه‌ی اصلی مخزن اجرا کنید (همان پوشه‌ای که README.md در آن است).

۵. آزمون کوتاه (smoke test)، گام به گام

این آزمون چهار اجرای ۳۰ ثانیه‌ای انجام می‌دهد تا مطمئن شوید همه‌چیز درست نصب شده است. حدود یک دقیقه طول می‌کشد.

python experiments/run_study.py smoke

خروجی چیزی شبیه این است (ستون time روی هر رایانه فرق می‌کند؛ بقیه‌ی عددها با کتابخانه‌های requirements.txt باید همین باشند):

[smoke] 4 jobs, 4 to run

profile    phi  rule                HO  unnec.  failed   UHO_pm  fail_pm   time
highway    0.5  A3 (control)      1608     599     103     3.99     0.69    10s
highway    0.5  memory, eta=8     1540     543     120     3.62     0.81    18s
street     1.0  A3 (control)       886     199      49     1.33     0.37    11s
street     1.0  memory, eta=0      886     199      49     1.33     0.37    19s

memory rule with eta = 0 equals the control (street): yes
event log of the highway control run: 1452 events in 550 places, rho = 0.32, skill = 0.04

خواندن این جدول:

ستونمعنا
profileالگوی حرکت کاربران
phiسهم مشترک سایه‌افکنی (بخش ۷)
ruleقاعده: کنترل یا حافظه‌دار با قدرت eta

سه نکته در این خروجی:

  • دو سطر آخر عیناً برابرند. قاعده‌ی حافظه‌دار با eta = 0 همان کنترل است و آزمون همین را می‌سنجد (سطر equals the control ... yes).
  • در دو سطر اول، حافظه با eta = 8 هندآور بی‌فایده را از 3.99 به 3.62 کم کرده و شکست را از 0.69 به 0.81 زیاد کرده است. اجرای ۳۰ ثانیه‌ای برای نتیجه‌گیری خیلی کوتاه است؛ این فقط آزمون سالم‌بودن زنجیره است.
  • سطر event log نشان می‌دهد لاگ رویداد نوشته و شاخص از روی آن حساب شده است.

اگر سطر آخر smoke test passed بود، همه‌چیز آماده است. خروجی این آزمون در results/smoke/ نوشته می‌شود و به نتایج اصلی دست نمی‌زند.

۶. مثال کوچک و تغییر یک پارامتر

python examples/quickstart.py

این اسکریپت یک سناریوی کوچک می‌سازد (۱۰۰ کاربر در بزرگراه، ۶۰ ثانیه)، کنترل و قاعده‌ی حافظه‌دار را روی آن اجرا می‌کند و شاخص را از لاگ کنترل حساب می‌کند. خروجی:

UDN-40, highway, 100 users, 60 s, phi = 1.0, d_corr = 50 m

metric                                      A3    memory    change

unnecessary HOs per user-minute          4.710     2.790      -41%
unnecessary-handover ratio               0.441     0.327      -26%
mobility failures per user-minute        0.360     0.460      +28%
outage [%]                               0.892     1.222      +37%
delivered / demanded rate                0.970     0.953       -2%

ستون change تغییر نسبی قاعده‌ی حافظه‌دار نسبت به کنترل است؛ عدد منفی یعنی کمتر شده است.

تغییر یک پارامتر. فایل examples/quickstart.py را با یک ویرایشگر متن (مثلاً Notepad) باز کنید. بالای فایل این سطرها هستند:

PROFILE = "highway"     # pedestrian | vehicular | street | highway | train
USERS = 100             # number of users
T = 60.0                # length of the test run [s]
WARM = 60.0             # length of the warm-up of the memory rule [s]
SEED = 1                # seed of the environment, the trajectories and the shadowing
PHI = 1.0               # shared share of the shadowing variance
D_CORR = 50.0           # decorrelation distance of the shadowing [m]
HYST, TTT = 4.0, 0.1    # A3 hysteresis [dB] and time-to-trigger [s] of both rules
ETA = 24.0              # strength of the memory [dB]

فقط یک عدد را عوض کنید، فایل را ذخیره کنید و همان فرمان را دوباره بزنید. چند آزمایش پیشنهادی:

تغییرچه چیزی را می‌آزمایدنتیجه‌ی نمونه
PHI = 0.0سایه‌افکنی هیچ بخش مشترکی ندارد؛ مکان چیز کمتری درباره‌ی نتیجه می‌گویدتغییر هندآور بی‌فایده از -41% به +17% می‌رسد و skill از 0.16 به 0.01
PROFILE = "pedestrian"کاربران کند؛ رویداد کم در مکان‌های زیادتغییر هندآور بی‌فایده +7%؛ فقط 1.1 رویداد در هر مکان و skill برابر -0.01
ETA = 0.0حافظه خاموش؛ دو ستون باید عیناً برابر شونددر همه‌ی سطرها 0%

این اجراها کوتاه و تک‌seed هستند و عددهایشان نوسان دارد؛ نتیجه‌های مقاله از اجرای کامل بخش ۱۰ می‌آیند.

۷. مدل سایه‌افکنی به زبان ساده

سایه‌افکنی کند میان یک کاربر و یک سلول، جمع سه بخش است:

بخشانحراف معیاررفتار
مشترکsigma_sیک میدان ثابت روی نقشه برای هر سلول. هر کاربری که از یک نقطه بگذرد همان مقدار را می‌بیند
خصوصیsigma_pبرای هر کاربر جدا؛ در طول مسیر خودش آرام تغییر می‌کند و به کاربران دیگر ربطی ندارد
سریع1.5 dBتغییرات زمانی با زمان همبستگی 1 s

مجموع توان دو بخش اول ثابت است و فقط سهم‌ها عوض می‌شوند:

sigma_s^2 + sigma_p^2 = (4 dB)^2
phi = sigma_s^2 / (sigma_s^2 + sigma_p^2)
  • phi = 1: همه‌ی سایه‌افکنی مشترک است. آنچه در یک مکان برای یک کاربر پیش آمد، برای کاربر بعدی هم پیش می‌آید؛ پس حافظه‌ی مکانی معنا دارد.
  • phi = 0: هیچ بخش مشترکی نیست. هر کاربر در همان مکان چیز دیگری می‌بیند.
  • d_c (در کد d_corr): فاصله‌ای که پس از آن سایه‌افکنی عوض می‌شود. d_c کوچک یعنی تغییرات ریز و پرتعداد.

پژوهش همه‌ی ترکیب‌های phi از مجموعه‌ی 1, 0.75, 0.5, 0.25, 0 و d_c از مجموعه‌ی 12.5, 25, 50, 100, 200 متر را می‌آزماید (۲۵ خانه). خانه‌ی phi = 1 و d_c = 50 m «محیط مرجع» نام دارد. در کد، تابع shadow(phi, d_corr) در experiments/common.py این تقسیم را انجام می‌دهد.

۸. قاعده‌ی حافظه‌دار و کنترل آن

قاعده‌ی MemA3 (فایل memstudy/rule.py) همان A3 است، با این تفاوت که حاشیه برای هر «مکان» و هر سلول مقصد جدا تعیین می‌شود:

margin = h + eta * (risk - mean risk)        clipped to [0, 9] dB
risk   = P(unnecessary) + P(early failure) - P(too late)

به زبان ساده:

  • نقشه به خانه‌های 40 m تقسیم شده است. برای هر (خانه، سلول مقصد) چهار شمارنده نگه داشته می‌شود: مفید، بی‌فایده، شکست زودهنگام، دیرشده.
  • اگر در یک خانه هندآور به یک مقصد معمولاً بی‌فایده بوده، risk بزرگ است و حاشیه بالا می‌رود (هندآور سخت‌تر می‌شود). اگر آنجا معمولاً پیوند پیش از هندآور قطع شده، risk منفی است و حاشیه پایین می‌آید (هندآور زودتر انجام می‌شود).
  • mean risk همین مقدار برای کل شبکه است. با کم‌کردن آن، میانگین جابه‌جایی صفر می‌شود؛ یعنی قاعده حاشیه را همه‌جا با هم بالا یا پایین نمی‌برد، فقط میان مکان‌ها فرق می‌گذارد.
  • خانه‌ای که هنوز سابقه ندارد همان حاشیه‌ی h را می‌گیرد (به کمک kappa = 3 مشاهده‌ی فرضی). شمارنده‌ها با ثابت زمانی 600 s کم‌کم فراموش می‌شوند.
  • eta قدرت واکنش بر حسب dB است.

کنترل. با eta = 0 این قاعده دقیقاً A3 با همان h و همان TTT است. در همه‌ی مقایسه‌ها h = 4 dB و TTT برابر 0.1 s است؛ این تنظیم A3 در اجراهای مقدماتی برای همین چیدمان به دست آمده است. هر دو قاعده مسیر حرکت، سرویس و سایه‌افکنی یکسان می‌بینند، پس هر تفاوتی در نتیجه فقط از جمله‌ی حافظه است.

گرم‌کردن. پیش از هر اجرای آزمون، قاعده‌ی حافظه‌دار 240 s روی مسیرهای دیگری در همان محیط اجرا می‌شود تا جدولش خالی نباشد.

انتخاب eta. یک بار و روی seedهای جدا (101 و 102) انجام شده است: از میان 2, 4, 8, 12, 16, 24 آن‌هایی که نرخ شکستشان از A3 با 3 dB و 0.3 s بیشتر نیست نگه داشته می‌شوند و از میان آن‌ها مقداری که کمترین هندآور بی‌فایده را دارد برگزیده می‌شود. نتیجه در results/tuned_eta.json است: eta = 24.

سپس رویدادها بر اساس (خانه، سلول مقصد) گروه می‌شوند و این عددها حساب می‌شوند (فایل memstudy/repeatability.py):

ناممعناچطور بخوانیم
rhoهمبستگی درون‌گروهی z: چه سهمی از پراکندگی نتیجه‌ها به «مکان» مربوط است0 یعنی مکان هیچ نمی‌گوید؛ 1 یعنی مکان همه‌چیز را تعیین می‌کند

نکته‌ی اصلی: در محاسبه‌ی این عددها هیچ قاعده‌ی حافظه‌داری دخالت ندارد. یافته‌ی پژوهش این است که rho به‌تنهایی اثر حافظه را پیش‌بینی نمی‌کند، ولی n و skill می‌کنند: اگر skill از حدود 0.03 بیشتر باشد حافظه سود می‌دهد و اگر کمتر باشد ضرر.

۱۱. خواندن runs.jsonl

هر سطر این فایل یک اجرای کامل است و به شکل یک شیء JSON نوشته شده: فهرستی از «نام: مقدار». فایل را می‌توان با هر ویرایشگر متنی باز کرد، ولی سطرها بلندند؛ خواندن با چند سطر Python راحت‌تر است. این متن را در فایلی به نام look.py در پوشه‌ی اصلی مخزن ذخیره کنید:

import json

rows = [json.loads(line) for line in open("results/runs.jsonl", encoding="utf-8")]
print(len(rows), "runs")

# reference environment, highway: control against memory rule
ctrl = [r for r in rows if r["block"] == "ref" and r["profile"] == "highway" and r["kind"] == "A3" and r["T"] == 240]
mem = [r for r in rows if r["block"] == "ref" and r["profile"] == "highway" and r["kind"] == "Mem"]
a = sum(r["UHO_pm"] for r in ctrl) / len(ctrl)
b = sum(r["UHO_pm"] for r in mem) / len(mem)
print("control", round(a, 3), "memory", round(b, 3), "change %", round(100 * (b / a - 1), 1))

و اجرا کنید:

python look.py

۱۴. تغییر یک پارامتر در کل پژوهش و اجرای دوباره

برای آزمودن یک ایده، اول از examples/quickstart.py شروع کنید (بخش ۶). اگر می‌خواهید کل پژوهش را با یک تغییر تکرار کنید:

  1. پوشه‌ی نتیجه‌ی تازه بسازید تا نتیجه‌های مخزن دست‌نخورده بمانند و با نتیجه‌های تازه قاطی نشوند. در PowerShell:
$env:MEMSTUDY_RESULTS = "results_new"
  1. پارامتر را عوض کنید. ثابت‌های پژوهش بالای فایل experiments/run_study.py هستند:
ENV, USERS = "UDN-40", 300
H0, TTT0 = 4.0, 0.1
ETAS = (2.0, 4.0, 8.0, 12.0, 16.0, 24.0)
T_RUN, T_WARM, T_LOG = 240.0, 240.0, 720.0
PHIS = (1.0, 0.75, 0.5, 0.25, 0.0)
DCORRS = (12.5, 25.0, 50.0, 100.0, 200.0)

مثلاً برای آزمودن هیسترزیس 3 dB به جای 4 dB، مقدار H0 را 3.0 کنید. پارامترهای خود قاعده (مثل kappa یا tau_f) در memstudy/rule.py و پارامترهای شبیه‌ساز در SimParams داخل hosim/simulator.py هستند.

  1. اجرا کنید:
python experiments/run_study.py
python experiments/analyze.py
python experiments/make_figures.py

هشدارها:

  • همیشه با پوشه‌ی نتیجه‌ی تازه کار کنید. run_study.py اجراها را با id می‌شناسد و هر id را که در runs.jsonl ببیند دوباره اجرا نمی‌کند؛ اگر پارامتری را عوض کنید که در id نیست (مثل USERS) و پوشه همان قبلی باشد، هیچ اجرای تازه‌ای انجام نمی‌شود.
  • make_figures.py شکل‌ها را در figures/ می‌نویسد و روی شکل‌های قبلی می‌نشیند. اگر شکل‌های مخزن را لازم دارید، پیش‌تر از آن‌ها رونوشت بگیرید.
  • برای کوتاه‌کردن زمان می‌توانید PHIS و DCORRS را کوچک کنید (خانه‌ی مرجع را نگه دارید). analyze.py با همان فهرست‌ها کار می‌کند، ولی شکل‌های fig_sweep و fig_index همه‌ی ۲۵ خانه را می‌خواهند؛ در آن صورت نتیجه را از summary.json یا runs.jsonl بخوانید (بخش‌های ۱۱ و ۱۲).
  • برای بازگشت به پوشه‌ی نتیجه‌ی اصلی، PowerShell را ببندید و دوباره باز کنید.
